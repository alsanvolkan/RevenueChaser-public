# Storage flow today

Per dataset: the source, the function that writes it, the DuckDB file and table, the key and write rule, and how long the rows stay. Source basis: Carried over from the private repo alsanvolkan/RevenueChaser at main f2d74a1c (2026-10-21), whose history this repo does not share: the 2026-10-22 migration re-rooted the public repo. The dataset rows, writers, sources, keys, write rules and retention below are the private repo's last reviewed record and were not re-read against this repo. The 173 path:line cites are therefore unverified here: the files mostly carry the same names, but the line numbers point into commits this repo has no copy of, and two cited files moved (core/ohlc_cache.py -> module_swing_potential/ohlc_cache.py, module_spx_gamma/cftc.py -> core/providers/cftc.py). Re-reading every cite against this repo is its own pass; until it runs, treat a line number here as a hint and the code as the source of truth; no store read or network call. `:NNNN` = core/rawstore.py manifest line; R2/C2/O2 = lineage v2 rows; uw.py = core/providers/unusual_whales.py. Page view: see the RevenueChaser Data Flow artifact.

**Write rules:** `upsert` = one row per key; a new fetch overwrites that row; `replace per` = all rows of the group are deleted, then the new rows written; `replace all` = the whole table is deleted and rewritten in one transaction; an empty batch is refused unless the caller passes allow_empty=True (core/rawstore.py:2900-2937); `append` = rows are added; nothing removes them; `file` = a JSON file in a folder per date.

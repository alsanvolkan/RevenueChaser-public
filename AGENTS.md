# Project instructions for AI agents

Three things govern almost every change in this repo: where data is **stored**,
how it is **retrieved**, and how it is **tested**. Each has a document that is
the source of truth. Read the one that covers what you are about to touch —
these summaries exist to tell you *which*, not to replace it.

in `docs/`. `docs/` holds only reference documents that describe how the system works

## 1. How data is stored

→ [`docs/data_architecture.md`](docs/data_architecture.md)

Two folders, one rule each:

- **`.store/`** is **DURABLE** — it holds three DuckDB files that cannot be
  regenerated by the app: `raw.duckdb` (structured raw + derived data + the
  identity/GICS spine, incl. `sec_company_*`), `edgar.duckdb` (EDGAR content:
  `edgar_documents` metadata, `edgar_facts`, `edgar_financials`, `chain_*`) and
  `prices.duckdb` (the daily price tables). A fourth, `history.duckdb`, appears with
  the first recorded board run. Never `rm -rf` it; treat them like database files.
- **`edgar_docs/{cik}/{accession}.html.gz`** is the one **file-based durable
  artifact** (raw 10-K/20-F HTML; dir via `RC_EDGAR_DOCS_DIR`). Backed up as a
  tree, not a DuckDB snapshot. Likewise the SPX Gamma tree, which the nightly backup
  mirrors incrementally (additive, verified).
- **`.cache/`** holds **regenerable artifacts** (rendered HTML/JSON, PNGs,
  downloaded zips). Clearable any time; a re-run rebuilds it.

If deleting it loses *history* or *ingested* data → `.store/` (or `edgar_docs/`).
If deleting it only costs a re-run → `.cache/`.

**The hot-path rule:** anything filtered, scanned, or joined across records is a
typed column, never a JSON blob. If a new reader scans or joins on a field that
currently sits inside JSON, promote it to a column in the same change — that is
a normal migration, not a redesign.

**Paths come from `core/config.py`.** Derive new path constants from
`OUTPUT_DIR` / `DATA_DIR`, never from `BASE_DIR` directly, or they escape the
`RC_STORE_DIR` / `RC_CACHE_DIR` redirect that keeps tests off real data.
`core/tests/test_store_layout.py` enforces this.

When you add or change data, decide *before writing code* whether it belongs in
`.store/`, `.cache/`, or as a file, and follow the per-table typed/JSON
conventions in the doc.

## 2. How data is retrieved

→ [`docs/data_retrieval.md`](docs/data_retrieval.md)

Every board has exactly two paths, and conflating them is the most common bug in
this repo:

> **Fetch** (`POST /run/<module>`, with the `X-RC-Panel` header) updates the store
> over the network, then recomputes and re-caches the board.
> **Refresh** (`GET /view/<module>?refresh=1`) drops the `.cache/` artifact and
> re-derives the board from `.store/raw.duckdb` with **zero network calls**.

Rules that follow from it:

- **Refresh must never touch the network.** This is asserted, not assumed — the
  e2e tier counts provider requests across a refresh and fails if any occur.
- **A board that needs no network must not require credentials.** Gating a
  store-only render on an API key makes it fail for no reason when a token
  expires.
- **A run that finds nothing must say so.** Write the artifact with an explicit
  empty state and raise `jobs.JobMessage`; returning early leaves a stale (or
  missing) file and the UI silently does nothing.
- **Fetches are async jobs.** `POST /run/*` returns `202` + a job id; poll
  `/api/job/<id>`. One worker drains the queue sequentially.
- **Every write sends `X-RC-Panel`.** Any method other than `GET`/`HEAD`/`OPTIONS`
  needs that header with a non-empty value, or the dashboard answers `403`
  (same-site CSRF, #231). A board's own `fetch(..., {method: "POST"})` adds it; from
  a shell: `curl -X POST -H "X-RC-Panel: cli" http://127.0.0.1:8000/run/<job>`. In a
  test use `core.tests.panel_client.panel_test_client(app)`; a test of the 403 itself
  uses the bare client. Detail: `docs/data_retrieval.md`.
- **New providers get an env-overridable base URL.** A URL inlined at the call
  site has no seam and cannot be tested. Credential messages belong in
  `core/credentials.py`, which names the variable, the file, and where to get a
  key.

If you add a board, register it in four places:

1. `_MODEL_ONLY_RENDERERS` in `app/dashboard.py` (it derives `_STORE_REFRESHABLE`), or
   Refresh silently degrades to a plain iframe reload;
2. `STORE_BACKED` (client, `templates/dashboard.html`), for the same reason;
3. `TABS` / `_module_file` in `app/dashboard.py`;
4. a hostile-payload entry in `core/tests/board_fixtures.py` (`BOARDS`), which the
   board HTML guard renders in both tiers. `test_registry_covers_every_board` fails
   until it exists. A sub-page that has its own `.html` (the Rotation trail page) is a
   `Board` of its own.

## 3. How data is tested

→ [`docs/testing_framework.md`](docs/testing_framework.md) (unit)
→ [`docs/e2e_testing.md`](docs/e2e_testing.md) (end-to-end)

Two tiers, both required for a change to be done.

### Unit — the default run

```bash
./app.sh test              # or: .venv/bin/python -m pytest
```

- Tests live **next to the code they test** (`<package>/tests/test_<module>.py`).
- **Every change adds unit tests** covering the new or edited behaviour.
- **Every change passes the whole suite** — run the full `pytest`, not a `-k`
  subset. Green on your own tests is not done. In Claude Code sessions, CI runs the
  full unit and e2e suites on the PR, and builders run the tests of the packages
  they touch (`CLAUDE.md` → Tests).
- No test touches the network, today's date, or real `.store`/`.cache`.

### End-to-end — before you claim a board works

```bash
./app.sh test-e2e          # opt-in; boots the real dashboard
```

Unit tests prove a function is right. They do **not** prove a board works —
regressions that broke whole tabs (a range picker that ignored its range, a
button that did nothing) have passed the full unit suite. If your change touches
a board's fetch, refresh, routes, or rendering, exercise it end to end.

**A test that cannot fail proves nothing.** After writing an e2e test,
reintroduce the bug it targets and confirm it goes red with a message that
explains itself. This is not ceremony: the first sector-rotation range test
passed with the bug fully present, because it asserted on something the board
never renders.

## 4. Backlog & roadmap

Backlog, roadmap and feature ideas live in this repository's **GitHub issues**, never
in local files. When a task or question mentions a feature idea or a roadmap item, read
the issues first — and never recreate a `future_ideas/`-style folder.

**Everything is an issue, and every issue is a sub-issue of its area epic:** slices,
review findings and research questions alike. A plan cites the issue numbers it
implements.

## 5. Agent orchestration

These rules apply to every agent:

1. **User asked for a plan** (`/plan …`, "make a plan", "plan: …", "plan this
   first") → **plan**. The user decides this; do not override it.
2. **Protected area** → **plan**, and build only after an explicit go.
   Protected: board / filter / ticker-picker work, data health, universe
   refetch, 10-K sync, `_SCHEMA_VERSION`, anything that writes `.store/`.
   Asking *about* a board changes nothing and needs no plan.

### Rules for the execution agent

- **One slice per run.** Implement exactly the brief or plan you were given;
  do not pull in the rest of a roadmap.
- **Touch only the files in scope.** The working tree is often dirty with
  unrelated WIP; never `git add -A`, never revert hunks you did not write.
- **No commits, no pushes, no live `.store/` writes**, no `_SCHEMA_VERSION` /
  manifest edits unless the plan names them. Those belong to the reviewer.
- **TDD per §3.** Tests next to the code, no network, full suite green.
- Your "tests passed" is a claim, not proof: the reviewer re-runs the named
  tests and the full suite and checks the diff against the scope.

### Rules for the reviewer

- Snapshot `git status --short` before launch; diff it after — only planned
  files may change.
- Re-run tests yourself; mutation-check tests you did not watch being written.
- Apply live-store mutations and commits yourself, and only when asked. Warn
  the user on every schema-version bump (§ Working style).

## Working style

- **Never claim something works because the code looks right.** Run it. The
  harness exists so you can.
- **Report outcomes faithfully.** If tests fail, say so with the output; if a
  step was skipped, say that.
- Schema-version bumps ship a downloadable store checkpoint — there is no
  automation, so **warn the user to do it manually**.

## 6. Dashboard design rules

- **Global metadata lives only in the shared parent top header** (`templates/dashboard.html`): the `Regime` badge and the last-run/sync timestamp. Never duplicate these inside a per-tab report.
- **Per-tab report top bars:** left title (`h1`) + subtitle; right at most `Last sync: <friendly date> EOD`. No `Regime` badge, no raw scan timestamp (`YYYY-MM-DDTHH:MM:SS`).
- Applies to every tab: Earnings Radar, SPX Gamma, Implied Probability, Financials, UW Interaction, Co-movement, Value Chain, Relatedness, Sector Rotation, Asymmetric Growth, Swing Potential, Fundamentals, SEC 13F, LEAPS. **Remove** Earnings Radar v2 and ER v2 Calibration (tabs, routes, `module_earnings_radar_v2/`) — see `docs/dashboard_ui.md` §8.
- **Ticker pickers are searchable comboboxes**, not native `<select>`. Type matches ticker **and** name; ranking is exact ticker → ticker prefix → ticker contains → name prefix → name contains. Closed label is `TICKER — full name`. Shared widget belongs in `RevenueChaser/core/reporting_common.py` (`docs/dashboard_ui.md`).
- **Universal filters** on equity-universe boards, **filters first then ticker combobox**: Detail level (only if coarse/medium/fine exists), search + `{n} names in {k} groups`, Market Cap (default All, min/max $M), Earnings, Index, Sector cascade (sector → industry), then a **Theme** dropdown of pinned NMF **coarse** labels. Import from `reporting_common`; do not fork. Applies to Co-movement, Value Chain, Relatedness, Sector Rotation, **Implied Probability, LEAPS (every tier, the Watchlist too), Earnings Radar (every row, including watchlist and the excluded section; Index, Market cap, Sector, Theme — no Earnings facet; the kit ANDs with the board's search and chips), and SEC 13F (Index, Market cap, Sector, Theme — no Earnings facet; the kit ANDs with the board's search; off-spine tickers are `Unclassified` with no cap)**. Sector Rotation keeps plotting `ROTATION_ETFS`; the Theme pick maps each coarse group to its ETF (KRE, SMH, XLK, …) per `docs/dashboard_ui.md`. Implied Probability: filters only narrow the combobox; retire `#oipd-ticker` in the parent header.
- **Board HTML trust boundary (ADR-X1, #144, #175).** Boards are same-origin iframes, so one
  unescaped string has the shell's authority. Every string a board renders (issuer names, 10-K
  snippets, theme names, provider fields, request parameters) reaches a page only through the
  helpers below:

  - **Python:** `core/html_safe.py` — `esc` (text or a quoted attribute), `script_json`
    (a value inside an inline `<script>`), `fill` (one-pass placeholder substitution).
    Never `str.replace` a placeholder, and never define another escaper.
  - **Client JS:** `html_safe.ESC_JS` (`rcEsc`) for anything put into `innerHTML`. Every
    filter snippet that calls it embeds it, so a page defines it once; a page that calls
    `rcEsc` without defining it throws a `ReferenceError` the first time the handler runs.
  - **One escaper rule:** no second `esc`, `tcEsc`, `escapeHtml` or `.replace(/[&<>"']/g, ...)` chain
    anywhere. `core/tests/test_one_escaper_175.py` scans the sources and every rendered board.
  - **Handlers read `data-*`, never an interpolated value:** `onclick="setSector(this.dataset.sector)"`,
    not `setSector('{sector}')`. The browser decodes an attribute before the JS string is
    parsed, so an HTML-escaped value still ends the string at a quote.
  - **Jinja:** HTML templates run with autoescape on; a trusted fragment (a Plotly chart) is
    wrapped in `Markup` where it is passed in, not marked `| safe` in the template. Markdown
    templates stay unescaped (they are not HTML).
  - **URLs:** `esc` does not neutralise a `javascript:` href. A link built from data takes an
    `http(s)` allowlist first (`module_settings/report.py::_ibkr_login_href`).
  - **Routes:** a ticker taken from a URL is normalised (`strip().upper()`) and then checked
    with `_valid_ticker`; an invalid one is a `400` that does not echo it.
  - **The guard:** `core/tests/board_fixtures.py` renders each board from a payload in which
    every text field holds `H(field)`, and the static (`test_board_html_guard.py`) and
    browser (`module_testing/e2e/test_board_html_browser.py`) tiers fail if it executes
    or lands raw. Do not mark a board `open_item` to get green; fix the sink.
